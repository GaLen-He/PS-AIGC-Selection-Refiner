# AIGC选区提交/整图分层 0.5.30

## 单任务重试与可见反馈
retryPendingTasks 以明确的任务 ID 集合调用 resumePendingTasks，不再误启动其他暂停任务。每次有效恢复清除旧错误并持久化实时消息，重复点击不会创建第二次贴回；消息同步到任务卡片，失败和未连接的提示在弹窗内可见。已处理结果缓存仍在时无需平台连接；离线恢复不会以空客户端启动网络自动重试。未收到成功确认仍保留原任务、缓存与预建层身份，任务完成后的报告不会复活已删除任务。
失败任务未运行时允许单独/批量清除追踪，清除不删除缓存、不改变 PSD、不取消平台任务。主任务按钮移到顶部。兼容写入及回滚诊断完整保存和显示。
本次未改变 capture.js/reservation.js/writer.js 或像素运输路径。putPixels 原生 -1 根因尚缺少实机证据，不通过切换文档或重建图层掩盖；本次离线测试仅验证恢复逻辑和 UI。

## 先贴回、后清理
选区、实时分层及恢复任务均先确认像素贴回并提交历史，再从待处理列表移除任务，最后执行可选的四角字符处理。贴回之前仅按需处理透明背景，不调用字符识别；下载原图保留至确认贴回，贴回失败不会提前删除。字符处理失败只返回提示，不回滚已贴回图片，也不重新加入取回队列。
字符处理使用独立事务及短期凭据，绑定原任务、原文档、原目标层及像素范围；原文档有后续编辑则跳过，避免覆盖用户操作。清理历史独立于首次贴回，可以单独撤销。分层每张确认贴回后处理自己的四角，再整理下一张；平台生图提交仍并发，图层顺序仍由提交时预建槽确定。无检测变化时不再重复写入 PS。
沿用透明空白区删除孤立字符、有底图局部插值修补的本地算法；不是 Photoshop 污点修复画笔，仍可能漏检或误判。本次不启用会切换活动文件的旧 JSX 工具路径，优先保证原结果可贴回。

## 透明像素兼容
仅当 RGBA putPixels 返回原生 -1 且原事务成功回滚时，尝试一次 RGB 加透明蒙版的兼容写入。原选区蒙版通过短 modal 读取，在原坐标重建并乘以结果 Alpha；写入限定提交时预建的结果层和蒙版，不缩小边缘选区、不切窗、不补建层。兼容失败回滚此次事务并保留原错误及 compatibilityError/compatibilityPhase；后续恢复仍可使用原图。
该兼容路径通过离线模拟测试，原生 -1 尚未在真实 Photoshop 中复现，不能据此宣称全部 PNG 或边缘问题已解决。

## 回贴错误隔离
旧 writer 在 putPixels 的 finally 中直接调用 image.dispose()，清理异常会覆盖写入异常，或将成功写入误报为 putPixels 失败并触发历史回滚。现在立即释放缓冲区为尽力清理，失败仅返回非致命提示；实际写入异常仍回滚并保留原错误。活动文档保护标记 verifyActiveDocument，历史提交标记 resumeHistory，不将后续步骤错误统一归为 putPixels。成功提交历史后才记录幂等完成，重试不会重复写入已确认的任务。
不透明条带采用 RGB 三通道，混合透明条带保留 RGBA 四通道；全透明条带跳过，首个可见条带 replace=true。全透明结果在进入 modal 前拒绝，不虚报空层成功。校验目标为普通像素层且未锁定透明像素；故障附带尺寸、坐标、通道数与目标层 ID，不包含平台凭据。
离线回归覆盖缓冲区清理失败、原错误保留、原点、贴边、整画布与透明像素几何；不收缩选区或添加切窗兜底，仅兼容路径更新结果层的透明蒙版。已复现的是错误归类/清理故障，不是原生 Photoshop -1 的全部根因，边缘选区实机结果仍待验收。

## 透明结果、恢复及任务进度
processSelectionPendingTask 在 Background=transparent 时调用既有 cutoutLayer/chromaKey，不依赖 cleanupText 开关。普通不清理任务仍走原旁路；prepared 缓存重试不重复处理，处理异常保留平台原图。真实 Alpha 保留，可验证的纯绿背景按原规则处理；已检查的若干结果为 Alpha 全 255 的棋盘格图片，不伪称透明，也不盲目删除。
writer 只在 LayerKind.GROUP 上递归读取 layers，避免对普通像素层访问组专用属性。原生字符串、冻结错误归一为可追加元信息的 Error；保留 number/code、phase、stripe 与 rollbackError。仅校验明确发现的身份/槽/层级失效标记 recoveryBlocked；属性读取抛出的临时宿主异常仍可重试。显式文档/图层定位、条带传输、modal、历史事务与活动窗口保护保留；通道选择及清理异常隔离如上。
task-progress.js 同时注册 CEP 浏览器全局与 CommonJS 导出，任务存档/控制更新时重绘五阶段进度。列表使用独立弹出面板，默认按提交时间倒序，可反向排序；不抢输入焦点，不伪造平台百分比。每条失败任务可按 ID 重置重试预算，不重置其他任务的安全阻断，不调用生成接口。完成确认后的任务从待处理列表移除。
暂停且未运行的任务可确认后单独或批量移出追踪，存档权威删除并清空相关 lastLayerRun，不删除下载图片。容量预留计入并发提交，最多 20 个待处理任务；超限旧队列完整保留并阻止新提交，不丢弃可恢复任务。设置保存或分层准备阶段抛错时释放容量预留，尚未调用生成接口。
修正 JSX 在空图层选择时误调用 selectNoLayers，恢复通道再恢复图层选择。角落清理沿用本地删除/插值修补，不宣称已调用 Photoshop 污点修复画笔。

## Home 页面与面板重载恢复
原 CEP 未发送 com.adobe.PhotoshopPersistent，隐藏或 Home 生命周期可能卸载面板，导致内存中的提交回调、轮询和本机桥接关闭。现在启动时以 APPLICATION 作用域和真实 extensionId 申请保活，不在隐藏时撤销保活，也不保持 Photoshop modal 或输入焦点。
任务、连接设置从仅 localStorage 改为独立用户存档优先、localStorage 兼容。按宿主标识及完整版本隔离，避免不同 Photoshop 进程/版本误认旧文档；存档不在签名 CEP 目录或图片清理目录内。首次读取迁移旧缓存，写临时文件、fsync、rename 原子替换；已完成的空列表权威优先于陈旧浏览器缓存，API key 不写进任务列表或发布包。
连接构造完成后立即恢复已存 trace，不等待模型目录完成。原 helperSessionId、documentId、预建槽身份与尺寸验证全部保留，不重提交生图，不按文件名认领旧任务。用户完全退出 PS、助手实际重启或平台 trace 尚未返回前发生进程崩溃，不在自动回贴保证范围；Home 保活旨在避免正常导航卸载丢失尚未收到 trace 的回调。
离线回归覆盖保活事件、空浏览器缓存重载、旧缓存不复活已完成任务、模型目录未完成先恢复、原 trace 回贴和写盘失败保留旧存档；不等于实际 Home 页面视觉验收。

以实际安装的 0.5.23 为基线，改动提交取图路径，保留中断恢复和结果像素回贴实现。

## 本次范围
选区与分层不再先在 Photoshop 保存整张 PNG：JSX 一次记录原文档、选区和预建结果槽，UXP 用明确 documentID、historyStateID 异步读取所需区域，长边限制 2048，CEP 再编码 PNG。0.5.24 错把 getPixels 放在 modal scope 外，实际宿主拒绝执行；0.5.25 把 getPixels、getData、像素拷贝与 dispose 放在同一短 executeAsModal 中，interactive: true，不激活目标文档。取得执行作用域后再次检查原文档、尺寸、历史 ID 和截止时间，取消时停止提交；RGBA 转换、PNG 编码和上传在作用域外执行。原生选区蒙版在预建槽时一次创建，不经全尺寸灰度往返传输。
renderReturnPixels、fitResultToSelection、evalHost、capture、reservation、background-return 以及旧 JSX PNG 导出内核保持原实现；writer 限于上述校验、通道选择和清理/错误隔离。回归测试比较恢复、传输、回贴函数及旧导出内核。新提交路径不调用旧 PNG 导出函数，预览兼容路径仍保留。
缓存缩小返回的 sourceBounds 按 2^level 还原原图坐标；CEP 按原选区或整图比例补白，以保留裁边后的相对位置。读取与 PNG 编码发生在短宿主准备操作结束之后。
重开面板时恢复非安全阻断任务的自动取回资格，清除上一次面板的重试耗尽标志和退避时间；仍沿用原 trace、文档与预建图层，不重新生图。当前面板内的失败重试仍限次数并退避，避免不停占用 Photoshop。
只有助手明确返回 placed: true 才删除选区任务及缓存；未确认结果保留待继续取回。会话改变、缺少预建层、目标被删除等明确安全阻断不自动解除，不能保证完全重启 Photoshop 后旧任务自动贴入。
本次未定位或修复 Photoshop -1 的宿主根因；恢复回归通过不代表该接口错误已解决，也不是静默性能实机证明。

## 沿用的任务恢复机制
旧版本只为网络错误或助手断连启用 autoResume，普通 Photoshop -1 在 placing 阶段会关闭恢复资格；resumePendingTasks 进入恢复时也提前写入 false，面板此时关闭将永久遗失恢复资格。
现在恢复开始与 placing 阶段保持 autoResume，普通回贴异常也进入重试队列；lastRecoveryError 保存经过脱敏的消息、phase、number、code 与 stripe。回贴按 30 / 60 / 120 / 240 / 300 秒退避，连续 5 次失败暂停，可通过紧凑的“继续取回”按钮重置预算。
recoveryBlocked 处理会话、槽与文档身份失效，不自动循环。原版本 autoResume=false 且保有原会话与预建槽的 placing 任务在重开面板时迁移恢复资格。任务仍按原 traceId 查询或下载，不调用生成接口。
模型目录读取与恢复解耦；已下载缓存存在则直接回贴，缓存缺失重新下载原 trace。分层在真正调用回贴前持久化 placing，未确认成功的图层继续排队。分层忙时不运行短周期空转恢复。
截图中的 Photoshop -1 原始宿主调用仍未实机定位；保留具体阶段与错误码，避免把所有错误都误报成助手断连。本次不移除必要的 putPixels，不改 history 或 modal 行为。
完全重启 PS 后 helperSessionId 改变；不能靠重用的 documentId / layerId 安全认领旧任务。旧结果保留并显示 PNG 路径，面板重开与 PS 重启不是同一保证。

## 回贴架构调整
本机 PS2024 Required/UXP/app.js 的 createPixelLayer、createLayerGroup、Layer.move、name setter、delete 内部存在目标文档 select。最终 activeDocument 相同不能证明没有 A→B→A 的瞬时激活。
提交开始时在当前原文档中一次建透明像素层、空结果组，按模板排序并放入对应画板。选区蒙版由原生 reveal-selection 创建；恢复原选中层和 RGB 通道后才在后台读取像素，不在导出或网络等待结束后再次检查当前窗口来预建层。
context.slot / task.slot 持久化 layerId、parentId、groupId、名称、reservationId 与 maskPrepared。回贴 writer 仅 putPixels 和 history，不执行 DOM 创建、移动、命名、删除或 putLayerMask；所有像素 HTTP 请求在 modal 之外预取。
无槽旧任务、槽被删除 / 改名 / 移动、原画板消失、会话或尺寸变化时保留 PNG，不走强制激活兜底。异步结果直接写槽，顺序不依赖完成时间。失败写入回滚，重复完成在助手会话内确认，helper 重启后旧会话任务不认领。
预建与结果写入分别是短 history 操作，不跨网络等待持有事务。取消 / 上传失败可能留下透明槽；不后台删除槽，以免再次激活目标。用户绘制槽或更改蒙版暂不能完整识别，因此明确要求不要编辑预建层。
Imaging 接口与 history / modal 的宿主内部 UI 行为仍需一次实际双窗口验收；离线接口测试不等于无闪动视觉证明。

## 构建与测试
开发目录运行 build-signed.ps1，再运行 make-package.ps1。私钥和 DPAPI 加密密码只在开发工作区 tools/adobe-signing/private，不随包分发。
安装包含 Adobe 官方验签工具与原许可。包 SHA256 与工具 SHA256 防止下载或解压损坏；这些哈希不是独立可信发布证明。签名用于完整性校验，不代表 Adobe Marketplace 审核或公司批准。
证书由官方工具免费自签，有效期十年；没有可信时间戳，证书过期前必须重新签发分发。不会把证书导入用户系统。
使用 node --test test/*.test.js 运行离线测试（模拟 Photoshop、任务持久化和定时器、临时假 APPDATA、真实 Adobe 验签）。
每次签名输出到新的暂存路径，验签并检查内嵌清单版本后才替换发行 ZXP，防止签名工具复用旧目标文件却报告成功。安装包只带分发白名单，不带测试、源码快照、私人证书或本机连接令牌。

## 未解决边界
UXP helper 仍是未签名 External 实验方案，正式 UXP 发布和实际宿主加载未验收；只复制/登记不构成签名。PS2024/2026 或公司策略拒绝该助手时本包不能承诺全功能可用。
原 0.5.14 PNG 导出内核不改，但任务提交不再使用它。预建层与原生蒙版仍是短宿主操作，大尺寸蒙版及 getPixels 的宿主内部耗时无法仅凭离线测试保证小于 1 秒。后台回贴绑定提交文档、画板、预建槽与助手会话，不做旧路径降级。真实静默效果、负坐标画板读取和 modal 交互影响仍需实机验收。
非标准重命名插件目录、多用户和系统级重复安装需进一步诊断，安装器只处理固定用户目录中的本插件，不清理其他目录。
